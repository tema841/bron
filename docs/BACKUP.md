# Резервное копирование и восстановление

Требования:
- PostgreSQL и утилиты `pg_dump`, `pg_restore`, `createdb` той же или более новой версии, что и сервер БД;
- в Windows утилиты лежат в `C:\Program Files\PostgreSQL\<версия>\bin`.

Пароль вводится по запросу или через переменную `PGPASSWORD` текущего окна терминала. В файлы и инструкцию пароль не записывается.

## 1. Контрольная запись

В интерфейсе создайте будущее бронирование и запишите его номер, например №42: «Компьютерный класс 204», через 3 дня, 12:00–13:00.

## 2. Резервная копия

```bash
pg_dump -h localhost -U postgres -Fc -f bron_2026-10-25.dump bron
```

`-Fc` — сжатый формат для `pg_restore`.

Где хранить копию:
- вне папки проекта, например в личной папке `Documents\backup`;
- в Git не добавлять: `*.dump` есть в `.gitignore`;
- копия содержит хеши паролей, поэтому её не публикуют.

## 3. Восстановление в отдельную тестовую БД

Рабочая база `bron` не удаляется и не меняется.

```bash
createdb -h localhost -U postgres bron_restore
pg_restore -h localhost -U postgres -d bron_restore bron_2026-10-25.dump
```

## 4. Тестовый экземпляр сервиса на восстановленной БД

Второй экземпляр запускается на другом порту и подключается к `bron_restore`.

Windows (cmd):

```bat
set PORT=8081
set DATABASE_URL=postgres://postgres:<пароль>@localhost:5432/bron_restore
npm start
```

Linux/macOS:

```bash
PORT=8081 DATABASE_URL=postgres://postgres:<пароль>@localhost:5432/bron_restore npm start
```

Переменные из командной строки имеют приоритет над `.env`.

## 5. Проверка

| Проверка | Как | Ожидание |
|---|---|---|
| Готовность | http://localhost:8081/health/ready | `{"status":"ready"}` |
| Вход | http://localhost:8081, логин ivanov | Вход выполнен |
| Ресурсы | Каталог | Те же 6 ресурсов |
| Контрольная запись | «Мои брони» или `GET /api/bookings/42` | Запись №42 на месте |
| Ограничения работают | Попробовать забронировать то же время, что у №42 | `409` «Ресурс уже занят в выбранное время» |

## 6. Результат

| Пункт | Значение |
|---|---|
| Дата | |
| Версия PostgreSQL (`psql --version`) | |
| Файл копии | |
| Контрольная запись | № |
| Вход, ресурсы, запись на месте | да / нет |
| Конфликт отклоняется (409) | да / нет |

После проверки тестовую БД можно удалить: `dropdb -h localhost -U postgres bron_restore`.

## Облачная БД (Render)

Используйте External Database URL из панели Render.

```bash
pg_dump "<External Database URL>" -Fc -f bron_render.dump
```

Восстановление и проверка — так же, в локальную `bron_restore`.
