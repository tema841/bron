# Описание API

Базовый адрес: `http://localhost:8080`. Тело запросов и ответов передаётся в формате JSON.

## Аутентификация

Защищённые маршруты требуют заголовок:

```
Authorization: Bearer <JWT>
```

JWT выдаётся при входе. В токене хранится только id пользователя, а роль сервер при каждом запросе берёт из БД.

## Формат ошибки

```json
{
  "error": {
    "code": "BOOKING_CONFLICT",
    "message": "Ресурс уже занят в выбранное время",
    "traceId": "5b6023a0-7442-423f-a74e-755aab3e5576",
    "details": { "startsAt": "..." }
  }
}
```

- `details` есть только у ошибок `400`: в нём ошибки по отдельным полям.
- `traceId` также приходит в заголовке `X-Trace-Id` каждого ответа.
- Стек исключения, пароли, JWT и строки подключения в ответ не попадают.

| Код | Когда |
|---|---|
| 400 | Неверные поля (`VALIDATION_ERROR`), нет ключа (`IDEMPOTENCY_KEY_REQUIRED`), некорректный JSON (`INVALID_JSON`) |
| 401 | Нет или недействителен JWT (`UNAUTHORIZED`), истёк JWT (`TOKEN_EXPIRED`) |
| 403 | Административная функция для обычного пользователя (`FORBIDDEN`) |
| 404 | Запись не найдена или чужая (`NOT_FOUND`) |
| 409 | Конфликт времени (`BOOKING_CONFLICT`), ресурс отключён (`RESOURCE_DISABLED`), запись уже началась (`BOOKING_STARTED`), ключ с другими данными (`IDEMPOTENCY_KEY_REUSED`), логин занят (`LOGIN_TAKEN`) |
| 500 | Непредвиденная ошибка (`INTERNAL_ERROR`), подробности только в техническом журнале |

## Время

Даты передаются в ISO 8601 **со смещением**, например `2026-10-25T10:00:00+03:00` или `2026-10-25T07:00:00Z`. Ответы возвращают моменты в UTC (`...Z`). Дата в параметре `date` — московские сутки в формате `ГГГГ-ММ-ДД`.

## Вход

### POST /api/auth/register

Регистрация, всегда с ролью «пользователь». Доступ: все.

Тело запроса:

```json
{ "name": "Сидоров Пётр", "login": "sidorov", "password": "secret1" }
```

Ответ `201`: `{ "token": "...", "user": { "id": 4, "name": "...", "login": "sidorov", "role": "user" } }`.

Ошибки:
- `400` — имя 2–100 символов, логин 3–50 символов (латиница, цифры, `_ . -`), пароль 6–72 символа;
- `409 LOGIN_TAKEN`.

### POST /api/auth/login

Доступ: все.

Тело запроса: `{ "login": "ivanov", "password": "..." }`.

Ответ `200`: `{ "token": "...", "user": {...} }`.

Ошибки: `400` — пустые поля; `401` — неверный логин или пароль.

### GET /api/auth/me

Текущий пользователь. Доступ: вошедший пользователь.

Ответ `200`: `{ "user": {...} }`.

## Ресурсы

### GET /api/resources?q=&location=

Каталог **активных** ресурсов. Доступ: пользователь, администратор.

Параметры:
- `q` — поиск по названию, без учёта регистра;
- `location` — точное местоположение.

Ответ `200`:

```json
{
  "items": [ { "id": 3, "name": "Компьютерный класс 204", "description": "...", "location": "Корпус 2", "isActive": true } ],
  "locations": ["Корпус 1", "Корпус 2", "Корпус 3"]
}
```

Ошибки: `401`.

### GET /api/resources/{id}

Карточка ресурса, в том числе отключённого: у него `isActive: false`. Доступ: пользователь, администратор.

Ответ `200`: объект ресурса.

Ошибки: `401`, `404`.

### GET /api/resources/{id}/availability?date=ГГГГ-ММ-ДД

Занятые интервалы за московские сутки. Возвращается **только время**, без владельцев и целей. Доступ: пользователь, администратор.

Ответ `200`:

```json
{ "date": "2026-10-24", "timezone": "Europe/Moscow",
  "busy": [ { "startsAt": "2026-10-24T07:00:00.000Z", "endsAt": "2026-10-24T08:00:00.000Z" } ] }
```

Ошибки: `400` — неверная дата; `401`, `404`.

## Бронирования

### POST /api/bookings

Создание брони для **текущего** пользователя: владельца сервер берёт из JWT. Доступ: пользователь, администратор.

Заголовок (обязательный): `Idempotency-Key: <случайная строка до 100 символов>`.

Тело запроса:

```json
{ "resourceId": 3, "startsAt": "2026-10-25T10:00:00+03:00", "endsAt": "2026-10-25T11:00:00+03:00", "purpose": "Консультация по курсовой" }
```

Ответы:
- `201` — новая запись;
- `200` + заголовок `Idempotent-Replayed: true` — повтор с тем же ключом и данными, возвращается исходная запись.

Объект брони:

```json
{ "id": 8, "resource": { "id": 3, "name": "Компьютерный класс 204", "location": "Корпус 2" },
  "startsAt": "2026-10-25T07:00:00.000Z", "endsAt": "2026-10-25T08:00:00.000Z",
  "purpose": "Консультация по курсовой", "status": "active", "state": "active",
  "createdAt": "...", "cancelledAt": null, "cancelReason": null }
```

`status` — хранимый статус (`active` или `cancelled`). `state` — вычисляемое состояние: `active`, `started` (идёт), `completed` (завершена), `cancelled`.

Ошибки:
- `400` — неверные поля, правила времени, нет ключа;
- `401`;
- `404` — ресурс не найден;
- `409 BOOKING_CONFLICT` — «Ресурс уже занят в выбранное время»;
- `409 RESOURCE_DISABLED`;
- `409 IDEMPOTENCY_KEY_REUSED`.

### GET /api/bookings/my?state=

Собственные записи, новые сверху. Доступ: пользователь, администратор.

`state` — необязательный фильтр: `active`, `started`, `completed`, `cancelled`.

Ответ `200`: `{ "items": [ ...брони ] }`.

### GET /api/bookings/{id}

Просмотр записи. Доступ: владелец или администратор. Администратор дополнительно получает `owner` и `cancelledBy`.

Ответ `200`: бронь.

Ошибки: `401`; `404` — нет записи **или она чужая** (обычный пользователь).

### POST /api/bookings/{id}/cancel

Отмена. Доступ: владелец (своей записи) или администратор (любой записи).

Тело запроса: `{ "reason": "Аудитория на ремонте" }`. Причина обязательна, 5–300 символов, если администратор отменяет **чужую** запись.

Ответ `200`: бронь со статусом `cancelled`. Повторная отмена тоже отвечает `200` без изменений.

Ошибки:
- `400` — нет причины;
- `401`;
- `404` — чужая или несуществующая запись;
- `409 BOOKING_STARTED` — запись уже началась или завершилась.

## Администрирование

Все маршруты `/api/admin/*` доступны только администратору. Обычный пользователь получает `403`, без JWT — `401`.

### GET /api/admin/resources

Все ресурсы, включая отключённые.

Ответ `200`: `{ "items": [...] }`.

### POST /api/admin/resources

Тело запроса: `{ "name": "Аудитория 301", "location": "Корпус 3", "description": "..." }`.

Ответ `201`: ресурс.

Ошибки: `400` — название и местоположение 2–100 символов, описание до 1000.

### PATCH /api/admin/resources/{id}

Изменение или отключение. Любые поля из набора: `name`, `location`, `description`, `isActive` (true/false).

Ответ `200`: ресурс.

Ошибки: `400`, `404`.

При отключении существующие записи сохраняются, новые не создаются.

### GET /api/admin/bookings?date=&resourceId=&state=

Все записи с владельцами, до 500 штук.

Ответ `200`: `{ "items": [ ...брони с owner ] }`.

### GET /api/admin/audit?limit=100

Журнал аудита, новые события сверху. `limit` — не больше 500.

Ответ `200`:

```json
{ "items": [ { "id": 15, "at": "...", "actor": "admin", "action": "booking.cancel_by_admin",
  "objectType": "booking", "objectId": 2, "result": "success", "traceId": "...", "details": { "reason": "..." } } ] }
```

Действия в журнале:
- `booking.create` — с результатом `success` или `rejected`;
- `booking.cancel`;
- `booking.cancel_by_admin`;
- `resource.create`;
- `resource.update`;
- `resource.disable`;
- `resource.enable`;
- `seed`.

## Проверка состояния

| Маршрут | Ответ |
|---|---|
| `GET /health/live` | `200 {"status":"ok"}`: процесс работает |
| `GET /health/ready` | `200 {"status":"ready"}`, или `503 {"status":"unavailable"}`, если БД недоступна |

## Пример запроса через curl

```bash
curl -X POST http://localhost:8080/api/bookings \
  -H "Authorization: Bearer <JWT>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 7f6c1c1e-0b0a-4f2e-9b1a-1a2b3c4d5e6f" \
  -d '{"resourceId":3,"startsAt":"2026-10-25T10:00:00+03:00","endsAt":"2026-10-25T11:00:00+03:00","purpose":"Консультация"}'
```
