ИТОГОВАЯ РАБОТА «БРОНЬ БЕЗ КОНФЛИКТОВ» — ЧТО СДЕЛАТЬ

Код готов и проверен. Нужно запустить у себя, пройти проверки,
сделать скриншоты и выложить на GitHub.

----------------------------------------------------------------
0. ЧТО УСТАНОВИТЬ (если ещё нет)
----------------------------------------------------------------
- Node.js 20 или новее (nodejs.org, версия LTS)
- PostgreSQL 16 (стандартный установщик; пароль postgres запомнить)
- Postman
- Git
- DBeaver или pgAdmin — по желанию, чтобы смотреть таблицы

----------------------------------------------------------------
1. ЗАПУСК
----------------------------------------------------------------
1) Распаковать архив, открыть папку bron в VS Code,
   открыть терминал (Ctrl+`).

2) Создать базу bron (в DBeaver/pgAdmin или командой):
     createdb -U postgres bron
   Если команда не найдена — она лежит в
   C:\Program Files\PostgreSQL\16\bin

3) Скопировать файл .env.example в .env и вписать:
     DATABASE_URL=postgres://postgres:ТВОЙ_ПАРОЛЬ@localhost:5432/bron
     JWT_SECRET=любая_длинная_строка
     SEED_ADMIN_PASSWORD=admin123
     SEED_USER_PASSWORD=user123

4) В терминале по очереди:
     npm install
     npm run migrate
     npm run seed
     npm start

5) Открыть http://localhost:8080
   Логины: admin / admin123, ivanov / user123, petrova / user123
   Скриншот: каталог ресурсов.

----------------------------------------------------------------
2. ПРОТОКОЛ ПРОВЕРКИ (docs/PROTOCOL.md)
----------------------------------------------------------------
Большую часть проверок делает готовая коллекция Postman.

1) Postman → Import → файл docs/postman_protocol.json
2) Открыть коллекцию → вкладка Variables → вписать
   userPassword = user123, adminPassword = admin123 → Save.
3) Перед прогоном выполнить в терминале  npm run seed
   (сервер можно не останавливать).
4) Отправлять запросы ПО ПОРЯДКУ сверху вниз: сначала папка
   «00 Вход», потом 01, 02 … до конца.
   В названии каждого запроса написан ожидаемый код (400, 409 и т.д.).
   На каждом — скриншот с ответом.
5) Результат вписать в столбец «Фактический результат»
   docs/PROTOCOL.md, например «409, совпадает».

Что в Postman нет — делается руками:
- п.1 корректная бронь через сайт (ivanov): каталог → ресурс →
  дата, время → Продолжить → Подтвердить. Скриншот.
- п.10 гонка двух запросов. В терминале (второе окно, сервер работает),
  дата — через 3–4 дня, свободное время:
    node scripts/race.js ivanov petrova user123 4 2026-10-30T15:00:00+03:00 2026-10-30T16:00:00+03:00
  Должно быть: один 201 и один 409. Повторить 3 раза с другим
  временем (16:00–17:00, 17:00–18:00). Скриншот терминала.
- п.14 зайти ivanov и открыть http://localhost:8080/#/admin →
  «Раздел доступен только администратору». Скриншот.
- п.15 истечение входа: в .env поставить JWT_EXPIRES_IN=60s,
  перезапустить сервер (Ctrl+C, npm start), войти, подождать минуту,
  открыть «Мои брони» → «Срок действия входа истёк». Скриншот.
  Потом вернуть 1h.
- п.20 нет сети: заполнить форму брони, F12 → Network → Offline →
  Подтвердить → «Нет связи» → Online → «Повторить отправку».
  Скриншоты.
- п.22 F12 → значок телефона → ширина 360 → пролистать каталог,
  карточку, мои брони, админку. Скриншот.

----------------------------------------------------------------
3. РЕЗЕРВНАЯ КОПИЯ (через DBeaver, docs/BACKUP.md)
----------------------------------------------------------------
1) На сайте создать контрольную бронь (ivanov), запомнить её номер.
2) Копия: DBeaver → ПКМ по базе bron → Инструменты → Backup →
   отметить схему public → Формат: Custom → выбрать папку вне
   проекта (например Documents\backup) → Start. Скриншот.
   Если DBeaver спросит Local client — указать папку
   C:\Program Files\PostgreSQL\16\bin
3) ПКМ по Databases → Создать базу → имя bron_restore.
4) ВАЖНО: открыть SQL-редактор для bron_restore и выполнить
     CREATE EXTENSION btree_gist;
   Без этого не восстановится защита от пересечений.
5) Восстановление: ПКМ по bron_restore → Инструменты → Restore →
   Формат Custom → выбрать файл копии → Start. Скриншот.
   Предупреждение «schema "public" already exists» — это нормально.
6) Запустить второй сервер на восстановленной базе (команды в
   docs/BACKUP.md, раздел 4), открыть http://localhost:8081:
   войти, увидеть ресурсы и контрольную бронь, попробовать занять
   то же время → должна быть ошибка «Ресурс уже занят». Скриншоты.
7) Заполнить таблицу «Результат» в конце docs/BACKUP.md.
Файл копии в GitHub не класть.

Запасной вариант командами (проверен):
  pg_dump -U postgres -Fc -f bron.dump bron
  createdb -U postgres bron_restore
  pg_restore -U postgres -d bron_restore bron.dump

----------------------------------------------------------------
4. GITHUB И CI/CD
----------------------------------------------------------------
1) На github.com создать пустой репозиторий bron.
2) В папке проекта:
     git init
     git add .
     git commit -m "Бронь без конфликтов"
     git branch -M main
     git remote add origin https://github.com/ЛОГИН/bron.git
     git push -u origin main
   Проверить, что на GitHub НЕТ папки node_modules и файла .env.
3) GitHub → вкладка Actions → сборка зелёная. Скриншот.
4) Сломать сборку: в src/time.js в любом месте стереть одну
   закрывающую скобку }, затем:
     git commit -am "ошибка"
     git push
   Actions → красная сборка, Deploy помечен как пропущенный (skipped).
   Скриншот.
5) Вернуть скобку:
     git commit -am "исправление"
     git push
   Снова зелёная. Скриншот.
Шаг Deploy будет пропущен — это нормально (нет секрета Render).

----------------------------------------------------------------
ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ
----------------------------------------------------------------
- «Не задана переменная окружения» → нет файла .env (шаг 1.3).
- password authentication failed → неверный пароль в DATABASE_URL.
- relation "bookings" does not exist → не выполнен npm run migrate.
- В Postman всё 401 → не выполнена папка «00 Вход» или неверные
  пароли в Variables.
- Коды в Postman не совпадают → выполнить npm run seed и пройти
  коллекцию заново с начала.
Остальное — docs/DIAGNOSTICS.md.
